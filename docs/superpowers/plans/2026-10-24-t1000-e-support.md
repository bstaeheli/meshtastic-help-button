> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, release and document a Help Button UF2 for the Seeed SenseCAP T1000-E next to the RAK WisMesh Tag, marked untested until a community tester confirms it on hardware.

**Architecture:** No firmware change. The fork (`af64b92`) already handles the T1000-E through the same no-screen user-button path as the Tag; this repo only adds a second preset env, builds it by default, and documents the differences. The shared preset flags move into one `[help_button]` section so both envs stay in sync.

**Tech Stack:** PlatformIO ini interpolation, bash (`scripts/build.sh`), GitHub Actions, Markdown docs.

**Spec:** the task brief (no separate spec file). Research below is the evidence base.

## Review Focus

1. Power-on press: on the T1000-E the only button is also the power-on button. A wake press still held when `ButtonThread` starts could be seen as a click and send HELP. Pinned by tester checklist item T2.
2. Holding the button while plugged into USB at boot enters the bootloader (OTAFIX >= 2.5): a child holding the button while charging boots into DFU instead of the firmware. Pinned by T3 and documented in `docs/device-config.md`.
3. Buzzer loudness/pitch: the hint jingle (C5..) and the eight-note C3-C4 countdown may be inaudible or distorted on the T1000-E piezo. Pinned by T5/T6.
4. Wake after shutdown: release-then-System-OFF must not self-wake with the active-high pull-down sense. Pinned by T7.
5. Release artifacts: both UF2s in `dist/` and `SHA256SUMS`, T1000-E marked untested in release notes. Pinned by Task 3 Step 3 and Task 5.

## Risks

- **Power-on press sends HELP** (Review Focus 1): single button doubles as power key; not reachable on the Tag the same way. Mitigation if T2 fails: ignore presses that started before the button thread's first run (fork change, out of scope here).
- **Bootloader on boot hold with USB** (OTAFIX >= 2.5): docs only; no code mitigation.
- **Buzzer audibility** of low countdown notes (C3 ~131 Hz) on a small piezo; may need different notes per device (fork change).
- **Airoha GPS** may take longer to fix; `HELP no GPS fix` is more likely shortly after power-on.
- **Untested release**: a broken T1000-E UF2 is recoverable over USB (bootloader is separate), so the risk is limited to the tester's time.
- **Merge conflicts** with the concurrent OTA-removal change in the same files; start after it lands.
